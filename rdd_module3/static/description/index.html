POS: Factura Global Cliente (México)

Emite CFDI Global desde POS, crea una Factura Global Cliente (factura espejo) ligada a las órdenes, y soporta cancelación con sustitución usando Relación 04 (UUID origen).
Política del módulo: nunca se consideran reembolsos/negativos en ningún flujo de consolidación o timbrado.

Descripción general

Este módulo extiende el flujo estándar de Factura Global de México (l10n_mx_edi) para Punto de Venta (POS), agregando control de periodo global, fecha/hora de emisión, factura espejo y un flujo robusto de cancelación con sustitución sin duplicidades.

Concepto clave:
  • Periodo global (mes/año) se usa para <cfdi:InformacionGlobal Meses/Año> (siempre se fuerza al día 1 del mes).
  • Fecha/hora de emisión se usa para Comprobante@Fecha (reglas: no futura y máximo 72h hacia atrás).

¿Qué hace este módulo?

  • Timbrado CFDI Global (POS) con nodo InformaciónGlobal: Periodicidad + Meses + Año.
  • Factura espejo tipo cliente (account.move) creada automáticamente al timbrar el global solo en emisión original.
  • Vinculación y trazabilidad: órdenes POS quedan ligadas a la factura espejo (pos.order.global_invoice_id).
  • Cancelación con sustitución (Motivo 01):
    • Crea una factura sustituta en borrador con CFDI Origen = 04|UUID.
    • El usuario timbra la sustituta desde la factura.
    • Después, se confirma la cancelación del CFDI original en el wizard.
  • Blindaje SAT / estabilidad técnica:
    • Evita errores tipo singleton al cancelar/actualizar estado SAT agrupando por attachment.
    • Respeta el pipeline EDI para construir líneas idénticas al XML.
  • Política de datos: NO reembolsos y NO negativos. Si se detectan, el flujo se detiene con error.

Reglas del módulo (importante)

  • Reembolsos / negativos: prohibidos en consolidación y timbrado. Se excluyen órdenes refund y se bloquean líneas negativas huérfanas.
  • Periodo global: se fuerza al día 1 (ej. 2026-03-01) para cumplir con InformaciónGlobal.
  • Fecha/hora de emisión: no puede ser futura y no puede exceder 72 horas hacia atrás.
  • Idempotencia de sustitución (04):
    • Si existe sustituta en Borrador → se reusa (se actualiza desde el wizard y se abre).
    • Si existe sustituta en Aprobada/Posted → se bloquea y se muestra alerta (no se crea otra).
    • Si existe sustituta Cancelada → se permite crear una nueva en borrador.
Nota SAT: Para cancelar con Motivo 01, primero debe existir el UUID del sustituto. Por eso el flujo es: Crear borrador → Timbrar sustituto → Cancelar original.

Manual de uso

A) Emitir CFDI Global (emisión original)

  1. En POS, genera ventas normalmente.
  2. Ejecuta el proceso de Factura Global (wizard México).
  3. Llena estos campos:
    • Periodo global (mes/año) (obligatorio recomendado): se usa en InformaciónGlobal.
    • Fecha/hora de emisión (opcional): controla Comprobante@Fecha (máx. 72h / no futura).
  4. Timbrar CFDI Global.
  5. Al timbrar, el módulo crea la Factura Global Cliente (factura espejo) y liga las órdenes POS.

B) Ver la Factura Global Cliente

  • Desde la orden POS: campo/smart access Factura Global Cliente (abre la factura ligada).
  • Desde Contabilidad → Facturas: identifica facturas con marcas globales (p. ej. x_is_global_pdv).

C) Cancelación con sustitución (Motivo 01 + Relación 04)

  1. Abre el CFDI global original y entra al wizard de cancelación.
  2. Selecciona Motivo 01 (Comprobantes emitidos con errores con relación).
  3. Haz clic en Crear factura sustituta:
    • El sistema crea (o reusa) una factura en borrador con CFDI Origen = 04|UUID.
    • NO timbra en ese momento (solo prepara el borrador).
  4. En la factura sustituta (borrador), timbra normalmente (esto genera el UUID del sustituto).
  5. Regresa al CFDI original y vuelve a abrir el wizard de cancelación:
    • Si ya existe sustituto timbrado, el wizard detecta Tiene CFDI sustituto y oculta campos de periodo/fecha.
    • Solo debes confirmar la cancelación con Motivo 01.
¿Qué campos se llenan en reemplazo?
En el paso de crear borrador sustituto puedes definir:
  • Periodo global (mes/año) del sustituto (InformaciónGlobal).
  • Fecha/hora de emisión del sustituto (Comprobante@Fecha).
  • Forma de pago y/o Términos de pago del sustituto (según tu política PUE/PPD).

Campos técnicos relevantes

  • pos.order.global_invoice_id: liga órdenes POS → Factura Global Cliente.
  • account.move.l10n_mx_edi_cfdi_origin: en sustitución queda 04|UUID.
  • x_is_global_pdv, x_global_periodicity, x_global_period_date, x_cfdi_emission_datetime.
  • l10n_mx_edi_payment_method_id: forma de pago SAT (se toma por mayoría o 99).

Troubleshooting

  • Error por Fecha/hora de emisión: no puede ser futura y debe estar dentro de 72 horas hacia atrás.
  • Órdenes con reembolsos/negativos: el módulo las excluye y/o detiene el proceso por política.
  • No se encontró “Factura Global PDV”: crea el diario con ese nombre en la compañía.
  • Sustituta en Posted: el flujo se bloquea y pide regresar a borrador si necesitas modificarla.
  • Periodo incorrecto: valida el Periodo global (mes/año) usado para InformaciónGlobal.

¿Dónde lo encuentro?

  • POS → Órdenes: acceso a la Factura Global Cliente ligada.
  • Contabilidad → Facturas: facturas globales / sustitutas por CFDI Origen.
  • Wizard Factura Global (MX): captura Periodo global y Fecha/hora de emisión.
  • Wizard Cancelación CFDI: motivo 01 y creación/uso de sustituto.
Requisitos:
  • Diario Factura Global PDV configurado en la compañía.
  • Partner genérico GLOBAL PDV (por XML/data).
